# План реализации MVP

Дата: 11.11.2026. Статус: RP-01—RP-08 реализованы и проверены. Результаты — docs/verification.md.

## Результат

Пользователь выбирает город, вводит бюджет квартиры и желаемую площадь, получает до 3 разных ЖК с подходящим лотом либо явно помеченной расчётной стоимостью. Бюджет не превышается. Backend на Python хранит данные в SQLite и обслуживает один поисковый endpoint. Frontend на Vite с простым чёрно-белым UI.

## Решения и границы

- FastAPI + SQLAlchemy + Alembic; React + TypeScript + Vite; SQLite.
- Две основные таблицы: residential_complexes и apartment_lots.
- Квартира имеет комнаты, площадь, полную стартовую цену и время обновления источником.
- Управление каталогом через backend CLI, без дополнительных HTTP endpoints.
- Один ЖК = одна карточка. При нехватке показывать меньше трёх.
- Подробные контракты: docs/architecture.md, docs/api.md, docs/search.md, docs/data.md.
- Допущения: площадь от желаемой до +10%, актуальность 30 суток, реальные лоты выше расчётных. Эти параметры заданы планом и изменяемы до реализации алгоритма.
- Нет реальных лотов в исходных данных; отдельная demo-база необходима для демонстрации. Нельзя превращать цену за м² в вымышленную квартиру.
- За рамками: личный кабинет, админка, автоматический парсинг, дополнительные фильтры, карты, история цен, платежи, публичный деплой.
- Трудозатраты и календарь не оценивались: нет исполнителей, загрузки и исторических данных. Это не блокирует начало разработки.

### RP-03. Реализовать импорт ЖК и квартир

Статус: выполнена.
Зависимости: RP-02.
Основные файлы: backend/app/cli.py, backend/app/services/imports.py, backend/tests/integration/test_imports.py, data/lots.example.json.

Работа:
Импортировать data/complexes.snapshot.json. Для ЖК использовать полный snapshot/upsert: все поля обязательны, неизвестное значение передаётся null; перезапись известной цены null разрешена только явным флагом --allow-clear-price. Повторное применение исходного снимка не должно затирать более свежую дату/цену; конфликт источников возвращает ошибку с требованием явного выбора. Критерии приёмки:
Первый импорт создаёт ровно 15 исходных ЖК; повторный не увеличивает число записей. Две неизвестные цены остаются null. Ошибка одной строки откатывает весь импорт. Старый файл не затирает свежий лот. Demo-импорт не меняет реальную БД. Есть отчёт created/updated/unchanged/rejected.

Проверка и границы:
