# Правила подбора

## Зафиксированные требования пользователя

Город + бюджет квартиры + желаемая площадь; до трёх разных ЖК; стоимость квартиры в выдаче; таблицы ЖК и квартир; один поисковый endpoint; Python + Vite + MySQL; чёрно-белый UI.

## Продуктовые допущения MVP

1. Бюджет — жёсткий максимум полной стоимости, без налогов, ремонта, ипотеки и комиссий.
2. Желаемая площадь — минимум; допустим интервал [area, area × 1.10] включительно. Верхнюю границу сравнивать как Decimal без промежуточного округления. Это решение плана, пользователь отдельно допуск не задавал.
3. Сначала реальные квартиры; внутри группы — близость к желаемой площади, затем более свежая дата предложения, затем меньшая цена, затем complex_id, lot_id. Отношение площади и разница в м² дают одинаковый порядок внутри одного запроса.
4. Актуальный лот: активный, не demo, updated_at не позднее now и не раньше now − 30 суток, обе границы включены. now фиксируется один раз на запрос.
5. На ЖК выбирается один лучший лот, затем общий top-3. Другие лоты того же ЖК не занимают места.
6. Если у ЖК вообще нет реальных записей лотов, допустима оценка area × min_price_m2; округление итоговой цены до копеек ROUND_HALF_UP, затем проверка бюджета. Это ориентир, не предложение квартиры.
7. Если у ЖК есть хотя бы одна реальная запись лота, но все лоты неактивны, устарели или не подходят, расчёт не подставляется. Исторические записи не считать отсутствием информации.
8. Расчёт возможен только при min_price_m2 != NULL, известной дате price_observed_on и возрасте этой даты ≤30 суток. Будущая дата запрещена. Время оценки цены ЖК — 00:00 UTC указанной даты.
9. Все реальные кандидаты идут выше расчётных; расчётные сортируются по итоговой цене, затем complex_id. При дефиците ответ 0..2; неподходящие варианты не добавлять.
10. Demo-лоты по умолчанию не читаются. В явном локальном DEMO_MODE показывать только demo-лоты и помечать весь ответ/каждую карточку. Не смешивать демонстрационные квартиры с реальными оценками.

## Начальная выдача

Снимок 15 ЖК не содержит реальных квартир. Для большинства цен неизвестна дата публикации; дата проверки 11.11.2026 не делает цену свежей. Поэтому безопасный запуск с одним этим снимком может вернуть 0 результатов. Полноценный показ трёх вариантов готовится в отдельном demo-режиме; для реальной работы нужен импорт актуальных лотов или датированных цен. Не придумывать рыночные лоты.

## Обязательные проверки

- Стоимость = бюджет подходит; на копейку дороже не подходит.
- Площадь = желаемой и = 110% подходит; ниже минимума и выше границы не подходит.
- Три квартиры одного ЖК дают одну карточку.
- При одинаковых данных порядок стабилен.
- Лот ровно 30 суток подходит; старше на микросекунду — нет.
- Снятые, будущие и demo-лоты не попадают в реальную выдачу.
- ЖК с историческими лотами не получает расчёт вместо неподходящей квартиры.
- NULL-цена и неизвестная/старая дата цены исключают расчёт.
- Реальные кандидаты выше расчётных даже при более высокой стоимости.
- Неизвестный город не подменяется другим; недостаток результатов — нормальное состояние.
- Поиск не выполняет запрос к БД на каждый ЖК; проверить EXPLAIN и число запросов на фикстуре 100 ЖК/10 000 лотов.
