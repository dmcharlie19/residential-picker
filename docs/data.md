# Данные и импорт

Источник начального набора — исправленная таблица из этого чата, проверка ссылок выполнена 11.11.2026. Новая проверка рынка в рамках составления плана не проводилась. Снимок хранит 15 ЖК и ссылки на источники цены и срока.

Это не готовый каталог квартир: количество комнат, площадь, цена и даты реальных лотов в исходной таблице отсутствуют.

## Правила снимка

- «Остров» и «Петровская Доминанта»: min_price_m2=null — текущий минимум не подтверждён.
- «Светский лес»: строится, II–IV кв. 2028.
- Avant: сведения о Balance/Klassik и ключах сохранены раздельно в описании, Fabrik требует уточнения.
- NEVA HAUS: дата цены 2026-10-11, остальные даты цены не предполагать.
- housing_class сохранён из исходной таблицы, отдельная проверка классов не выполнена.
- Для «Отражения» 270 000 ₽/м² относится к конкретной большой квартире; доступность требует проверки.
- URL источников — ссылки, а не доказательство доступности квартиры сегодня. Часть сведений получена из поискового индекса, прямой доступ Циан ограничивался капчей.
- UTC-date проверки не подменяет дату источника, imported_at или дату обновления лота.

## Формат импорта лотов

UTF-8 JSON, объект schema_version=1 и массив lots. Поля каждой строки:
complex_slug, external_id, rooms, area_m2 (строка Decimal), starting_price_rub (строка Decimal), updated_at (ISO 8601 с timezone), source_url (URL или null), building (строка или null), is_active (boolean), is_demo (boolean).

Комнаты — целое 0..20, студия = 0. Деньги/площадь положительны и не выходят за точность БД. Ссылка только http/https. В production is_demo=true запрещено. Неизвестный complex_slug и дубли ключа внутри одного файла — ошибки, весь файл без изменений.

При повторном импорте те же ключи обновляются; older updated_at не может затереть более свежий лот. При равной дате и отличающихся содержательных полях выдаётся конфликт и весь импорт откатывается; равная дата с теми же данными — no-op. Обновление импортного времени при no-op не делает предложение свежее.

## Отдельные демонстрационные данные

В задаче RP-03 подготовить минимум 3 вымышленных ЖК на каждый город с подходящими demo-лотами, а также неподходящие/устаревшие варианты. Названия содержат «Демо», is_demo=true, ссылки не имитируют реальные источники. Дата demo-лотов задаётся относительно момента генерации. Demo-ЖК не входят в исходные 15 и в реальный режим; способ исключения — отдельная база для demo (без добавления третьей предметной таблицы).

## Реальные данные

Импорт реальных квартир — после получения датированных источников с указанием лота и его характеристик. Отсутствие исходных лотов блокирует реальную рыночную демонстрацию, но не разработку: контракт, алгоритм и UI проверяются на фикстурах. Сбор рыночных данных и автоматический парсинг не входят в MVP.
