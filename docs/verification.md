# Проверка реализации

Дата: 11.11.2026.

## Подтверждённые результаты

- Backend: pytest — 51 passed, на MySQL 8.4 в отдельной residential_picker_test. Без SQLite и без пропусков.
- Проверены бюджет до копейки, интервал площади, 30-дневная граница, будущие даты, снятые и demo-лоты, один ЖК на карточку, стабильный порядок, расчётная цена и запрет подмены исторических лотов.
- Проверены атомарный импорт, повторная загрузка, защита свежего предложения от старого, конфликты одинаковой даты, ошибки внешнего ключа, дубли и ограничения MySQL.
- Масштабная фикстура: 100 ЖК / 10 000 квартир; top-3 выдаётся не более чем тремя SELECT; EXPLAIN подтверждает использование индексов.
- Alembic: downgrade base → upgrade head на тестовой базе прошли; alembic check — No new upgrade operations detected.
- Backend контейнер Python 3.13 собран из requirements.lock; локальные тесты выполнялись Python 3.14.
- Frontend: Vitest — 12/12; typecheck и Vite production build прошли; npm audit при установке — 0 vulnerabilities.
- Chromium: 7 сценариев прошли, pageErrors=[]; два действующих origin через nginx и Python API, без подмены БД.
- Исходный импорт: created=15, затем unchanged=15, без дублирования.
- Demo seed: 9 вымышленных ЖК и 45 лотов в отдельной базе (54 созданные строки суммарно).
- API real возвращает demo_mode=false и 0 подходящих исходных предложений; demo возвращает demo_mode=true и 3 разных ЖК в бюджете.
- Приложения доступны только на локальных интерфейсах: 8080/8081; MySQL 13306/13307.
- Контейнеры и MySQL запущены; обе MySQL healthcheck проходят.
- После перезапуска обеих MySQL проверены сохранность: real 15 ЖК / 0 лотов, demo 9 ЖК / 45 лотов. Повторный импорт real снова unchanged=15.

## Браузерные сценарии

1. Невалидная форма не отправляется.
2. Три разных demo-ЖК в пределах бюджета.
3. Поиск в Москве, Санкт-Петербурге и Сочи.
4. Мобильная ширина 360 px без горизонтального скролла.
5. Нулевой бюджетный результат отображается как отсутствие подходящих вариантов.
6. Ошибка 503 отображается отдельно от пустой выдачи (HTTP-ответ подменён в браузерном тесте; реальное преобразование ошибки БД дополнительно проверено backend-тестом).
7. Реальный каталог не содержит синтетических квартир.

Снимки: docs/evidence/desktop-initial.png, desktop-results.png, mobile-results.png. Машинный результат: docs/evidence/browser-results.json.

## Воспроизведение

- scripts/test-backend.ps1 — выделенная тестовая MySQL.
- frontend: npm ci; npm test; npm run build.
- После запуска real/demo: npx playwright install chromium; npm run test:e2e.
- В этой среде использован уже установленный Chromium через BROWSER_EXECUTABLE_PATH.
- Полные команды запуска/миграций/импорта — docs/runbook.md.

## Ограничения и не выполненные действия

- Рыночных лотов в исходных данных нет; они не были придуманы. Для реального подбора нужны свежие квартиры или датированные минимальные цены.
- Цены и сроки из снимка не были повторно сверены с рынком в ходе разработки.
- Публичный деплой и проверка восстановления из реальной резервной копии не выполнялись; команды backup/restore описаны.
- В тестовом клиенте установленная Starlette выдаёт предупреждение о будущем переходе с httpx на httpx2. Оно не влияет на прохождение тестов и работу приложения.
